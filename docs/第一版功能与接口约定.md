## 1. 目标和边界

输入一个可构建的 Lean 4 项目、模块与指定的谓词定义，自动分析：

1. 谓词是否恒真、恒假。
2. 每个显式数据参数是否影响谓词真假。
3. 通过展开非递归定义，在调用方的整体语义中分析上述性质。

两条路线独立运行：Lean 自动证明；符号执行加 SMT。结果保留各自来源、原始输出和资源限制。第一版不要求提取 Lean 证书或将 SMT 证明重建为 Lean 证明。

第一版只分析显式指定的定义；不做项目全量扫描、递归及高阶分析、用户自定义前提、函数摘要、抽象解释或自动判断是否违反用户意图。支持定义调用不等于实现独立的调用点诊断或因果解释：先输出可定位的展开调用链；如无法确认退化原因，不给出推测性原因。

## 2. 性质的精确定义

设输入空间为各参数类型的笛卡尔积，参数 `i` 之外的参数写为 `z`。第一版只做**无额外前提的全局分析**；`caller` 分析的是其自身完整定义，并非任意人为限定的调用条件。

| 请求 | 请求为真的条件 | 请求为假的见证 |
| --- | --- | --- |
| `always_true` | `∀ x, P(x)` | `P(x)` 为假的一组输入 |
| `always_false` | `∀ x, ¬ P(x)` | `P(x)` 为真的一组输入 |
| `independent` | `∀ z u v, P(z,u) ↔ P(z,v)` | 固定 `z` 后，两组参数值 `u`、`v` 使真假不同 |

每个谓词生成两个恒值请求和每个参数一个独立性请求。零参数谓词仅生成两个恒值请求。所有输入类型均非空；不得把不支持的类型按空域处理。

展示层可由已确认的独立性得出“无影响”，由独立性反例得出“有影响”。恒真请求被推翻仅意味着有假值；恒假请求被推翻仅意味着有真值。两者均被推翻才说明谓词有真有假。两个请求没有完成时，不能据此断言性质。

## 3. 输入语言及支持矩阵

### 3.1 声明

- 目标是完全限定名称的透明 `def` 或 `abbrev`，返回 `Prop`；显式参数为下列基础类型。
- 允许无参数谓词；允许展开的非递归辅助定义返回基础类型或 `Prop`。
- 对待展开的调用图检测直接和间接递归；递归、`opaque`、外部实现、未找到函数体均返回 `unsupported`，不把调用视为任意值。
- 不支持隐式数据参数、类型类参数、依赖参数或返回类型、高阶参数和返回值、局部递归、量词、集合、自定义归纳类型。Lean 内置运算经 elaboration 后出现的类型类实例，前端可在已识别的具体运算中消解；其他实例或重载不得猜测。
- 显式数据参数按声明顺序确定稳定的 `index`，名称只作展示；分析对象中的编号从 0 开始。

### 3.2 类型及表达式

| 类型 | 第一版支持 |
| --- | --- |
| `Int` | 任意精度整数和字面量、一元负号、加减、整数常量乘法、等号及大小比较 |
| `Nat` | 自然数字面量、加法、截断减法、自然数常量乘法、等号及大小比较 |
| `Bool` | `true`、`false`、等号、否定及布尔与/或 |
| `Prop` | `True`、`False`、`∧`、`∨`、`¬`、`→`、`↔`；基础类型间的已支持比较 |
| 表达式结构 | 变量、`let`、已支持类型的 `if` / `ite`、非递归透明定义的完全应用 |

不支持除法、取模、变量乘变量、强制类型转换、整数溢出模拟、模式匹配和上述集合以外的运算。`if` 的条件须能转换为已支持的逻辑表达式，两个分支须为相同已支持类型。`Nat` 到 SMT 使用非负整数约束，减法使用 `ite (a ≥ b) (a - b) 0`，其他运算应保持 Lean 语义。

前端根据 elaboration 后的常量全名、类型和实例识别运算，不能按源代码符号或名称片段猜测。表达式类型不明、实例无法识别、调用非完全应用或中间表示包含未知节点时，SMT 路线停止并报告 `unsupported`。Lean 自动证明路线可以继续尝试；两条路线独立记录支持状态。

## 4. 外部工具与运行约定

- 原型验证优先使用本工作区已验证的 Lean `4.27.0-rc1`。该版本仅作为开发基线；分析其他 Lean 项目时，优先使用目标项目锁定的工具链和依赖。适配器与目标版本不兼容时明确报告，不悄悄切换版本。
- SMT 默认适配 Z3 的 SMT-LIB 2 命令行接口；cvc5 留作后续适配器。当前环境尚未发现可执行的 Z3 或 cvc5，具体固定版本和启动参数以安装后的兼容性冒烟实验为准，不能声称已验证。
- 使用 Python 3.13 作为第一版编排器的开发基线；Lean 提取器和目标生成部分使用与目标项目兼容的 Lean 组件。Windows 为当前开发环境，命令使用参数数组执行，不拼接 shell 字符串。
- 对每个请求、每条路线默认限时 10 秒，可由命令行覆盖；超时记 `unknown`，进程异常或输出不可解析记 `error`。资源限制、版本和耗时都要记录。
- 输出写入用户指定的运行目录；默认 `./sa-output/<run-id>/`。不修改被分析项目源码；若需要临时 Lean 文件，放在运行目录并通过项目环境加载。
- 第一版命令行约定：`sa analyze --project <path> --module <module> --decl <qualified-name> --backend <lean|smt|both> --out <directory> --timeout-seconds <n>`。`both` 是默认值。命令是预定接口，尚未实现。

## 5. 前端和中间表示

前端运行在目标 Lean 项目环境，读取 elaboration 后的声明类型和表达式，记录 Lean 版本、模块、完全限定声明名、参数索引及类型、调用引用和可获得的源码位置。源位置缺失时允许为 `null`。前端不能直接将未经解析的源码文本作为 SMT 语义依据。

第一版中间表示是 UTF-8 JSON，所有节点携带 `kind`、`type`；变量采用 `param` 的索引或 `let` 的唯一局部 ID，禁止依靠显示名称绑定。每种支持运算使用固定 `op` 和有序 `args`；常量携带值，整数以十进制字符串存储，避免宿主语言精度损失；调用使用完全限定名和已解析参数。`ite` 含条件、真分支、假分支，`let` 含局部 ID、值和主体。类型和节点集合按第 3 节逐项校验，任何不认识的构造均拒绝转换。

示例（仅展示节点结构）：

```json
{"kind":"op","type":"Int","op":"int.add","args":[
  {"kind":"param","type":"Int","index":1},
  {"kind":"int","type":"Int","value":"7"}
]}
```

依赖声明单独记录并使用引用；展开前检测循环。符号执行使用带类型表达式树和 `ite`，逻辑连接词均按 Lean 的命题语义编码。选择直接生成一个包含 `ite` 的查询，避免第一版必须枚举所有执行路径；它仍要保留条件语义。调用展开和表达式规模必须受限，达到上限时返回 `unknown`，不得仅使用已处理的部分得出确定结论。默认展开深度 32、表达式节点 100000，可配置并记录。

## 6. 请求接口

所有文件使用 UTF-8 JSON，版本字段为 `"1.0"`，新增不兼容语义时变更主版本。每个请求是一个独立 JSON 对象，ID 在本次运行内唯一，不能依赖参数显示名识别参数。

```json
{
  "schema_version": "1.0",
  "request_id": "Example.gate:param:2:independent",
  "target": {"module":"Example", "declaration":"Example.gate"},
  "property": {"kind":"independent", "parameter_index":2},
  "domain": {"kind":"all_inputs"},
  "timeout_ms": 10000
}
```

`kind` 为 `always_true`、`always_false` 或 `independent`；只有 `independent` 带 `parameter_index`。`domain.kind` 在第一版只能是 `all_inputs`，不接受条件约束；错误参数索引是输入错误。模块名、声明名和项目环境必须一同确定目标，不使用同名短名称自动猜测。

## 7. 结果、证据与汇总

```json
{
  "schema_version": "1.0",
  "request_id": "Example.gate:param:2:independent",
  "backend": "smt_z3",
  "status": "confirmed",
  "evidence_kind": "smt_unsat",
  "raw_status": "unsat",
  "witness": null,
  "witness_validation": "not_applicable",
  "elapsed_ms": 45,
  "tool_version": "actual-version",
  "artifacts": {"query":"requests/example.smt2", "stdout":"logs/example.out", "stderr":"logs/example.err"}
}
```

状态相对于请求中的性质：

- `confirmed`：Lean 目标成功或对应 SMT 反例查询为 `unsat`；必须填写证据类型。
- `refuted`：有实际反例，附具体输入。SMT 的 `sat` 模型先经中间表示解释器独立重放；无法重放或结果不符时只保留原始 `sat` 和候选模型，统一状态为 `unknown`，并记录原因。这里的重放检查模型与 IR 一致，**不证明 Lean 到 IR 的翻译正确**。
- `unknown`：策略未完成、求解器 `unknown`、超时、资源上限，或见证无法重放。
- `unsupported`：超出相应后端支持的类型、节点或能力。
- `error`：解析、进程启动、协议、输出或内部不变量发生错误。

`witness_validation` 取 `ir_replayed`、`lean_checked`、`unvalidated` 或 `not_applicable`；第一版不要求 `lean_checked`。见证值使用带类型的十进制字符串或布尔值，并按参数索引列出；独立性见证包含两组完整参数及两次谓词真假。

Lean 路线只在目标成功证明时返回 `confirmed`；普通 tactic 失败返回 `unknown`。第一版不要求 Lean 路线独立搜索反例，因此不能因为 Lean 证明失败而返回 `refuted`。SMT 路线对所有请求检查性质的否定：`unsat` 对应 `confirmed`，`sat` 且重放成功对应 `refuted`。常量检查也要保存具体查询及结果。

汇总保留每个后端的独立结果：只有一个后端有确定结果时展示该结果及来源；两个后端一致时展示双方；`confirmed` 与 `refuted` 冲突时展示 `conflict`、停止合并并保留完整证据，不能投票或自动判定谁正确。`conflict` 是汇总状态，不是单一后端结果。

## 8. 分析目标与调度

每个定义先生成所有请求，再分别分发到所选后端。后端之间不共享证明结论作为前提；默认直接展开支持范围内的调用。一个请求失败不应中断其他请求，但无法加载目标模块或构造共同输入时应明确报告整个目标失败。

Lean 路线按固定顺序尝试：展开目标及支持的辅助定义，先尝试 `simp`，再尝试 `omega`，最后尝试所选 Lean 版本可用的 `grind`。每次尝试需有独立状态及共享请求总时限；具体可用语法在冒烟实验中固定。不要把重用中间证明称为函数摘要。

SMT 路线必须生成可单独运行的 SMT-LIB 文件；对 `Nat` 参数、局部值及见证加入必要的非负约束。保留 `check-sat`、模型获取和实际命令。`unsat`、`sat`、`unknown` 应分别解析，模型解析失败不能给出有影响的最终结论。

## 9. 输出目录与退出状态

```text
<run-dir>/
  manifest.json             # 项目、工具、版本、配置和运行状态
  declarations/             # 提取出的定义和类型化 IR
  requests/                 # 求解请求、生成的 Lean 与 SMT 输入
  results/                  # 每请求每后端一个结果 JSON
  logs/                     # 标准输出与错误输出
  report.json               # 汇总，包含原始结果引用
  report.txt                # 人可读结论与限制
```

退出码：`0` 表示运行按计划完成（允许 `unknown` / `unsupported`）；`1` 表示输入、启动或内部错误导致运行不完整；`2` 表示存在后端结论冲突。退出码不是性质真假或分析覆盖率。冲突优先于普通未知；同时出现错误时在 `manifest` 中记录，优先返回 `1`。

## 10. 验收标准

1. 对 `gate`、`caller` 指定声明运行 `both`：在后端可用、未超时的条件下，得到项目设计文档第 3 节列出的结论；所有 `sat` 见证通过 IR 重放。
2. 两条路线分别记录原始目标、查询、工具版本、耗时和输出；SMT `unsat` 不标为 Lean 内核证明。
3. 有测试覆盖 `Int` 正负与零、`Nat` 的 `0 - 1 = 0`、`Bool`、`if`、`let`、嵌套调用与定义展开；针对有限枚举输入比对 Lean 与 IR/SMT 结果，重点覆盖截断减法和分支。
4. 测试各类 `unsupported`、工具缺失、超时、`unknown`、无效模型、坏 JSON 和冲突结果；不得输出确定性结论。
5. 恒真和恒假独立判断；测试一个有真有假的谓词，验证两项均 `refuted` 且见证不同。
6. 真实 Lean 项目之外，至少准备一个多层非递归调用示例、一个与 `gate/caller` 相似但不恒真的反例示例；对照手写 Lean 证明及直接 SMT 查询。

这些是实现后的验收条件，当前没有宣称已经满足。

## 11. 尚需冒烟实验确认的事项

- Lean 4.27.0-rc1 的提取器接口、`grind` 的实际可用性、目标项目版本兼容与临时模块加载方式。
- Z3 在目标环境的安装方式、版本和模型输出；Windows 进程控制和超时行为。
- 构造 IR 时 elaboration 后的具体常量和类型类实例，是否覆盖第 3 节规定的全部运算。
- `if` 的具体支持类型及表达式规模上限对实际项目的影响。

若冒烟实验与本约定冲突，应记录实际证据并修订文档，而不是默默改变结论语义。
